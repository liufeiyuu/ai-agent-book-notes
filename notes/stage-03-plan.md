## A. 工具设计：从函数到可调用能力

**需要掌握：**

- 工具名称、用途、使用条件、参数 Schema、返回结构与错误反馈的职责。
- 模型输出参数、本地校验、权限判断、真实执行的位置；结构正确还需要核对哪些业务条件。
- 专用工具、通用执行器和 Skill 的适用场景；工具粒度、返回信息量和参数保真性的取舍。

**最小实践：**先读已有[计算器工具](../experiments/minimal-agent-ts/src/tools/calculator.ts)和[工具执行器](../experiments/minimal-agent-ts/src/tool-executor.ts)，用成功计算、非法参数、除零区分校验失败与执行失败。

对照已有[读文件工具](../experiments/minimal-agent-ts/src/tools/read-file.ts)的目录限制，解释“参数格式正确”与“允许执行”的区别；本阶段不建设审批等待或恢复流程。

再为虚构的 `create_draft` 工具写规格：输入草稿正文，返回草稿 ID 或结构化错误，实际效果仅是向实验内存中的草稿集合添加记录。助手补齐规格、参数校验和核心保存逻辑，复用注册与执行器；学习者结合实际结果理解校验和保存行为，无需手写函数。

**完成证据：**工具规格、已验证代码、正常与错误输入输出；能说明一个接口设计取舍。

## B. MCP：亲自接通一个本地工具

**需要掌握：**

- Agent 应用、MCP Client、MCP Server、实际工具实现各自的位置。
- 初始化、能力协商、工具发现、调用与结果回传的基本顺序；Function Calling 与 MCP 的关系。
- 工具被发现、实际被调用、结果进入模型上下文分别需要什么证据。
- 工具数量变多时发现与按需加载的作用；本单元不实现搜索平台。

**最小实践：**用 TypeScript 将已有 `calculator` 包装成一个本地 MCP 工具，采用一种本地连接方式，通过真实 MCP Client 完成初始化、发现、成功调用和非法参数反馈。客户端可以是小型测试程序，不要求界面或多应用接入。

保留“Client 请求 → Server → 原有函数 → 返回结果”的记录，与直接调用函数的路径对照。读一段 Agent 工具适配位置，说明结果应如何变成 Tool Result。

**完成证据：**真实协议交互记录、接入图、一处 Schema 或结果映射修改及学习者对其效果的解释（代码可由助手完成）。客户端测试不是模型自主选工具的证明；没有新的模型运行就明确标注这一边界。
