## 目标与学习方式

面向已有前端和 TypeScript 经验、尚未系统学习 Python 的学习者，建立阅读、运行和排查 Python 小项目的基础，随后进入 Stage 6 的 HTTP 与 FastAPI 服务链路。已有编程概念只做必要对照，重点解释语言写法、模块边界与实际行为。

沿用 [AGENTS.md](../AGENTS.md)的约定：每次带学前从 README 定位并完整读取本计划；默认由助手实现、调试和验证，学习者理解行为、结果与取舍。手写函数、补代码或从零重建项目不作为验收门槛；学习者主动选择动手时再记录其实际贡献。

每个学习块先对照与当前问题有关的官方资料短段，再看同一份输入输出与三到五处关键代码，用代表性失败和已有测试收尾。按一个完整问题推进，参考 10–15 分钟阅读量，不逐行讲完辅助代码，也不把已经理解的 Agent 概念重新从头讲一遍。

**2026-11-08 学习方式反馈：**学习者认为当前纯文字方式效果不理想，希望尝试公开视频，英文讲解可接受、优先有字幕。先提供候选课程与短段试看建议，暂停按原方式直接继续 C2 文字带读；建议采用“视频演示建立理解 → 现有项目对照 → 定点答疑”，官方文档用于核对或补缺。具体课程与选看范围仍待学习者选择或试看反馈，不把推荐记为已采用、已观看或已理解。原有核心目标与验收保留，课程全套作业、证书和完整课时不自动成为本阶段门槛。

学习者进一步明确，该偏好延伸至 Stage 5–10，希望围绕同一个项目持续跟视频学习，减少分散文字资料与多套课程之间的切换。下方保存主项目候选；选课讨论不启动项目实现，不把候选直接改成已采用主线，也不提前变更阶段验收。若确认采用，再把阶段要求映射到同一项目，已完成的环境与实验成果保留引用。

**同日目标进一步收敛：**学习者提供 TREK 并明确它是最感兴趣、最想学习和复刻的项目。后续选材优先支持旅游规划产品与 Agent 对真实行程的操作；邮件助手、PhiloAgents 与博客课程降为历史候选/按需资料，不再默认等待从这些项目中选一个。当前请求是寻找同类视频，不据此开始克隆、部署、模型调用或全功能复刻。TREK 是 TypeScript 全栈，可复用学习者已有基础；Python 是否继续作为主项目必需前置需结合具体实现路线调整，不擅自宣布 Python 已学完或删去历史证据。

## 原 CLI 实践方案（保留作按需参考）

本节及随后原学习块表保存先前方案与证据，新执行载体以上方“已采用的路线与投入估算”为准。未完成的 Python 能力在视频项目中继续，不要求先补完整个 CLI 才能开始 Corey。

最小成果是一个**本地 JSON 处理 CLI**，处理虚构的工具调用记录：

项目入口为 [`experiments/python-tool-records/`](../experiments/python-tool-records/README.md)。C1 建立环境与入口；C2 已实现固定内存样本的筛选、汇总与输出，下面的 JSON 文件读取、完整输入校验尚待 C4，不提前记为完整 CLI 已通过。

```text
读取 JSON 文件
  → 校验必需字段与取值
  → 筛选失败记录、按工具汇总
  → 输出统计或明确的错误
  → 用测试核对正常与失败行为
```

输入使用六条虚构记录，字段为 call_id、tool、status、duration_ms，见[固定样本](../experiments/python-tool-records/tool_records/samples.py)。学习者提出或讨论一条筛选/汇总规则，助手实现并核对修改前后结果；本轮由助手选取“全部失败→失败且耗时至少 500 毫秒”作具体对照，学习者理解尚待确认。该例用于串起前五块，不拆成多套项目，也不读取真实个人数据。

最后在同一小项目中加入受控异步假工具，观察一次成功和一次超时或取消，解释等待、任务与清理。沿用 Stage 4 的概念基础，聚焦 Python 的表达与调用关系；完成必要异步后再在 Stage 6 接模型和真实工具。

## 抓大放小的边界

- 先核对已有 Python 环境和项目约定，再选择一个最小入口；不预先承诺版本或安装方案。依赖只取本阶段必要部分，不重新搭建工具生态。
- 以同一份虚构数据串起语言、文件、异常和测试。复杂语法只有阻塞主线时才展开，不建立逐项语法考试。
- 测试用于区分正确行为与代表性错误；不把断言数量或全量覆盖率作为学习目标。助手运行通过与学习者理解分别记录。
- 异步限受控假工具和必要的等待、超时/取消机制，不重建官方 async-agent、不接付费模型，也不新建生产任务系统。
- Pydantic 与 FastAPI 留给 Stage 6；数据库、Worker、持久化与部署按后续路线接续。历史 TypeScript 的 RAG、记忆与工具实验不重写。
- 元类、复杂装饰器、解释器内部、多进程与性能优化等按需查阅；遵循路线已有边界，不为每个未展开的辅助细节建立必学欠账。
