# 引言

## 核心公式
```text
Agent = LLM + 上下文 + 工具
```

对应三种理解：

| 工程视角 | 直觉类比 | 强化学习视角 |
| --- | --- | --- |
| LLM | 大脑 | Policy（策略） |
| 上下文 | 眼睛 | Observation Space（观察空间） |
| 工具 | 手脚 | Action Space（动作空间） |

## 原书要点

## 1
实践在前，命名在后，这个顺序对企业级 Agent 开发有一个很实际的含义：如果你每次都要等到业界开始流行某个 Agent 名词才去实践，就已经慢了一步。 名词流行的时候，头部公司往往早已把对应的问题趟过一遍了。那么，怎样才能赶在名词流行之前就知道该怎么做？我认为最关键的有两点。
第一，拥有一个对 Agent 能力上限有极高要求的真实业务，并能持续获得真实的业务反馈。 
第二，必须建立评估（Evaluation）机制。 这也是本书反复强调的一点：没有评估，就没有进步。评估让你能分辨一次改动究竟是真的变好了，还是只是运气，从而让 Agent 的迭代方向不再依赖直觉。

### 2
本书的核心公式只有一句话：Agent = LLM + 上下文 + 工具。三者缺一不可。
更直观地说，就是大脑 + 眼睛 + 手脚。大脑（LLM）负责思考和决策，眼睛（上下文）决定 Agent 能看到什么信息，手脚（工具）决定 Agent 能做什么事情。（严格来说，“眼睛”只是一个粗略的类比：上下文不仅包含环境信息和对话历史，还包含工具定义等内容，也就是说 Agent “看到”的信息中也包括了“有哪些手脚可用”。这个隐喻旨在传达核心直觉：上下文是模型能感知到的一切信息。）

## 我的理解

Agent 就是 LLM ➕ 调用工具 ➕ 上下文

## 延伸问题

### 真实业务反馈怎样转化成可重复的评估数据？
真实业务反馈通常是零散、主观且不可直接复现的，例如用户投诉“没有解决问题”、客服发现 Agent 违规退款，或者开发者接管了失败任务。要把它转化为评估数据，需要完成以下过程：
保存完整轨迹
记录用户输入、上下文、模型回复、工具调用、工具结果、人工接管原因和最终业务状态。

定义可验证的成功标准
把“表现好不好”改写为明确指标，例如：
是否真正完成退款
退款金额是否正确
是否违反业务规则
是否调用了未经授权的工具
用户问题是否在规定轮次内解决

将典型反馈整理成测试案例
对失败轨迹进行脱敏，保存初始环境、任务、期望结果和评分规则，使其能在隔离环境中重新运行。

给案例添加分类和权重
标注失败属于感知、推理、工具执行、规则违反还是恢复能力问题。高风险问题应具有更高权重，安全违规不能被满意度等平均分抵消。

建立回归评估集
每次修改 Prompt、Skill、Harness 或模型后，都重新运行这些案例，确认新问题得到修复，同时旧能力没有退化。

持续补充边缘案例
将生产环境中新出现的失败不断加入评估集，形成：

真实任务 → 记录轨迹 → 人工反馈 → 提炼失败案例
       → 自动回归评估 → 修改系统 → 再次验证
关键点是：不要把用户满意度作为唯一指标。 用户可能因为 Agent 违规退款而满意，但系统实际上变得更危险。满意度应与任务成功率、规则违规率、隐私泄露率和越权操作率一起评估

### Harness、Skill 和 Loop Engineering 分别承担什么职责？
#### 概念	核心职责	解决的问题
Harness	为模型提供运行环境和安全保障	怎样让 Agent 可靠地完成一次任务
Skill	封装可复用的领域知识和操作方法	怎样让 Agent 知道某类任务应该如何做
Loop Engineering	设计跨轮次的持续执行与改进循环	怎样让 Agent 自主发现、推进并验证下一项工作

Harness
Harness 是模型之外的工程基础设施，包括：
上下文管理
工具接入
权限和行为约束
结果验证
错误重试、回滚和人工接管
它把模型的推理能力转化为可靠的任务执行能力。可以概括为：
Agent = Model + Harness
Harness = 上下文 + 工具 + 约束 + 验证 + 纠正

Skill
Skill 是按需加载的“任务说明书”，保存某个领域中可复用的知识、策略和操作步骤。
例如“处理退款申请”Skill 可以说明：
先查询哪些信息
如何判断是否符合退款政策
应调用哪些工具
哪些情况必须转人工
如何验证退款真的完成
Skill 通常适合表达可以用语言描述、会持续调整的策略；确定且不可违反的规则，仍应写进 Harness 的程序约束中。

Loop Engineering
Loop Engineering 关注的不只是一次任务如何执行，而是整个系统如何持续运转：
谁发现下一项任务
如何确定优先级
每轮如何观察真实结果
失败后是重试、换策略还是交给人类
什么条件下才算真正完成
本轮经验如何传递到下一轮
它要求每轮循环都获得来自真实环境的新信息。如果没有外部验证，Agent 只是在重复处理旧上下文，循环可能空转。

三者的关系可以理解为：
Skill 告诉 Agent“这类事情通常怎么做”
Harness 保证 Agent“这一次安全、可靠地做”
Loop Engineering 决定 Agent“接下来做什么，以及如何持续改进”
它们不是相互替代的框架：Skill 是 Harness 中的一类上下文资产，而 Loop Engineering 是在 Harness 之上组织长期自主运行的更大工程层次。
