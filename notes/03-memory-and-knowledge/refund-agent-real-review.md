# 真实退款 Agent：Stage 2 实践收尾

## 结论与范围

2026-09-13，Stage 2 选定知识主干、带学实践与场景验收完成，可以进入下一阶段。依据是学习者的实际运行、Top-K 受控对照、失败判断和最终口头复述，不是单凭助手完成代码或六例测试通过。

本记录整理学习对话中的结论，并保留反馈后的准确表述；不把修正后的完整讲解冒充学习者未经提示的原始回答。项目使用虚构商城数据，只做退货咨询判断，不执行退款。

## 一条请求怎样得到有依据的结论

以 H1001 的明确订单 Agent 案例为例：

1. 程序把用户问题和必要上下文发给模型，并按当前流程阶段提供工具。
2. 模型提出 `query_orders` 调用，Harness/Agent Loop 校验并执行。工具返回订单事实，程序把结果作为工具消息加入对话。
3. 下一轮模型提出 `search_policy` 调用。程序依据已查询订单的购买日期、品类和渠道限定政策范围，再进行检索。
4. `search_policy` 返回的证据已经包含命中知识块的原文、来源等信息；程序将此工具结果回传模型，不是在工具结果之外再凭空补一份知识块。
5. 模型结合用户描述、订单事实和适用条款给出答案；程序检查格式、流程、订单与引用，语义是否得到支持仍需人工核对。

三类信息不能互相代替：

| 来源 | 本例提供的信息 | 作用 |
| --- | --- | --- |
| 用户描述 | 外包装已拆、配件齐全、无损坏 | 说明商品当前情况；不是程序已经完成实物检测 |
| `query_orders` | 官方直营耳罩式耳机；购买于 2026-09-02；签收后 2 天 | 确定订单事实、适用范围和时间 |
| `search_policy` 的 `headphones-v2#1` | 适用 v2；7 个自然日内；允许外包装拆封，但需配件齐全且无损坏 | 提供本次判断依据 |

判断链：购买日期和渠道等匹配 v2 → 签收 2 天在 7 日期限内 → 用户描述符合拆封条件 → 返回 `eligible`。只有“2 天”不知道规则；只有“7 天”不知道订单是否满足规则。

模式边界：固定 RAG 由程序安排查询、检索和上下文组织；本项目 Agent 由模型提出工具调用，程序执行并限制必要阶段。Agent 并不意味着模型可以跳过必需的事实查询。

## Top-K 对照：结论没变也是实验结果

学习者亲自运行 normal 案例的固定 RAG 对照，并报告如下观察：

| 观察项 | Top-K = 3 | Top-K = 1 |
| --- | --- | --- |
| `ranking` 项数 | 5 | 5 |
| `hits` 项数 | 3 | 1 |
| 返回的块 | `headphones-v2#1`、`#2`、`#3` | `headphones-v2#1` |
| 最终状态 | `eligible` | `eligible` |
| 引用块 | `headphones-v2#1`、`#2` | `headphones-v2#1` |
| 回答差异 | 多出凭订单号向客服申请退货的说明 | 保留主要资格判断，未包含上述申请说明 |

实验解释：

- 假设：减少 K 会减少模型收到的证据，可能影响回答，但不一定改变最终判断。
- 变量：只调整 Top-K，保持案例、模型和索引等配置一致。
- 机制：本项目是业务范围过滤 → 向量相似度排序 → 取前 K 个，没有单独的精排模型。Top-K 是截取数量，不改变评分规则，也不要求重建文档向量。
- 结论：两次均保留了包含本例关键条件的 `headphones-v2#1`，因此资格判断仍有充分依据；少掉的证据影响了补充说明。
- 限制：“语义相关”不等于“证据充分”。不能由这一例推出 K = 1 对所有问题都足够，也不能把生成文字的每一处变化都确定归因于 K，模型输出还可能存在随机性。

## 失败应该定位在哪一层

| 观察 | 正确解释 |
| --- | --- |
| B1003 的品类是 `bone-conduction`，`ranking` 和 `hits` 都为空 | 没有适用政策；增大 K 不能恢复已被范围过滤排除的块 |
| 查单成功、政策检索成功但返回空结果 | 已完成搜索，缺的是适用条款；应说明 `insufficient_evidence`，不再声称已知订单事实缺失 |
| 模型没有调用工具，却输出格式合法的 `insufficient_evidence` | 状态字面正确不代表执行合格；仍可能因未查单、引用未知订单而失败 |
| 工具执行完成，模型却作出没有依据的结论 | 流程完成不等于回答正确，应检查生成与证据支持关系 |
| 引用文字确实来自某个知识块，却与判断无关 | 原文匹配不等于支持结论；运输包装建议不能证明退货资格 |

版本和条件判断也已练习：H1002 按 2026-08-20 的购买日期选 v1，以 30 日规则判断签收 12 天；E1004 的卫生封条已拆且无质量问题，应使用入耳式耳机例外，不能套用耳罩式耳机允许拆外包装的政策。

### 提前结束问题怎样修复

该修复由助手在用户授权后实现，学习者随后跟踪代码和 Trace 理解机制，不记录为学习者独立完成修复。

- 必需阶段限定工具和目标参数，并使用 `tool_choice: required`；流程进度取自工具成功返回的结果。
- 最终回答前检查必要查询是否完成；提前结束会被拒绝，但仍受原有轮数和时间上限约束。
- 成功搜索且结果为空算“查过”；工具执行报错不算成功，不能为了拿到非空证据无限循环。
- 格式恢复仅处理必要流程完成后的格式问题，不代替查单、检索或业务验证。

这些是组合修改。真实复验的改善不能单独归因于 `required`；在线运行没有触发 `final_rejected`，该分支由离线回放验证。详见[修复与真实运行记录](../../experiments/refund-agent-real/LIVE-RUN.md#提前结束故障与流程检查修复)。

### 自动评测能证明什么

JSON 合法、引用 ID 存在、引文匹配、缺失信息列表非空，都只是对应字段或约束的检查。它们不能自动证明模型正确理解政策、缺失信息真的缺失，或引文足以支持结论。内置案例的 `expected_decision` 使用预设标注，不能代替没有金标时的人工语义审查。

教学中的回答篡改检查是离线、内存内的评测演示，不是真实模型新生成的结果。6/6 是六个合成案例当次通过，不是生产可靠率。

## 索引收尾：原文、元数据和向量各做什么

准备阶段：政策正文和元数据 → 分块 → 为块生成 Embedding → 保存包含块原文、元数据和向量的索引。

提问阶段：按订单范围过滤 → 用同一 Embedding 模型生成查询向量（存在候选时）→ 计算相似度并取 Top-K → 取出命中块原文供回答模型阅读。

- 向量用于寻找相关内容，原文提供证据，元数据限定适用范围。
- `earbuds-v1.md` 的“卫生封条与质量问题”和“信息不足”分别生成 `earbuds-v1#1`、`earbuds-v1#2`；`#1` 是分块编号，不是排名。
- 改 Top-K 没有改变块内容或 Embedding 模型，因此已有文档向量仍可复用；不是“只要以前生成过就永远有效”。
- 政策正文变化后，当前块与旧索引不再一致。本项目检查指纹和块内容，拒绝使用失效索引；`ask` 不自动重建，需要执行 `npm run index`，重建可能产生接口费用。

2026-09-13 收尾演示：助手运行只读 `npm run inspect`，确认 14 个向量、4096 维、索引有效；随后仅在内存中把一个块的“7 个自然日”改成“10 个自然日”，调用校验函数，观察旧索引被拒绝。没有修改政策文件、重建索引或调用模型接口，不算学习者亲手完成了索引重建实验。

## 最终复述与反馈

学习者已经复述出模型提出 Tool Call、Agent Loop 执行、结果回传、模型结合证据作出判断的主线，并解释 Top-K 只改变返回范围，已有文档向量可复用。

收尾反馈修正了三处：

1. 本例先 `query_orders`，取得事实后再 `search_policy`，不是默认一轮同时执行两个查询。
2. 知识块已经包含在政策工具结果中，不是另一份独立来源。
3. Top-K 对照中结论不变，是因为关键证据仍充分，不仅仅因为命中了语义相近的文字。

结合此前已完成的订单/政策来源辨认、受控实验和失败判断，Stage 2 约定的核心验收通过，不再追加新一轮题目。

## 完成后不再追加的门槛

- 不要求背诵函数名、逐行读完源码或阅读全部测试。
- CLI 打印、HTTP 适配、序列化细节、数学推导和生产部署均按需回查。
- 独立业务 Prompt 编写、神经重排、自动压缩、持久化记忆和完整索引发布治理仍见[延后清单](../learning-backlog.md)，不阻止进入 Stage 3。
- 结业表示本阶段选定目标完成，不等于独立实现生产系统，也不填写精确的个人知识掌握率。

下一阶段建议从[第 4 章：工具](../04-tools/README.md)开始，先约定核心问题和结束标准。Stage 3 尚未正式开始，不把延后清单机械地全部塞进下一阶段。
