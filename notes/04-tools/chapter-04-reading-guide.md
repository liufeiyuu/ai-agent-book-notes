## 带读方式与时间

每轮先给原文标题和明确起止位置，只取约2–4个自然段或一张表；助手用短摘句或定位提示带读，再解释关键词，连接已做实验，最后说明这段需要掌握到哪里。用户不必独自啃完整章，不要求誊写笔记或每段答题。作者观点、助手举例和实际实验结论分别标明。

预计分6次左右，每次约10–15分钟，共约60–90分钟供后续安排；这是原计划定向阅读的补落实，不叠加新实验或重新设课时上限。与用户互动后按实际难度调整，不把助手读过资料记成用户已读。

特别校正：作者在能力形态处偏向通用执行能力，并讨论采用专用工具的理由。计算器是本课观察接口和 MCP 的教学样例；不能据此推导生产场景应为每项业务都建一个专用工具。书中的产品判断和性能数字带有场景前提，不等于协议强制规则或普遍保证。

## 第一小段：从表4-1 建立地图

定位“工具的分类”的开头说明、表4-1及其后示例；先不要进入“工具设计的通用原则”。

助手举例：读取仓库笔记是在取得信息；create_draft 改变了实验内存中的记录；把任务交给另一位助手是在分工；给用户发进度是沟通；订阅一个任务完成事件是在等待外部触发。一个实际工具可能同时承担多种效果，判断时看它实际做了什么，而非只看函数名称。这里先认识分类，不新增实现。

这段的阅读目标：看到一个工具，能辨认主要作用和谁发起交互。原文表格还帮助理解第四章与第六章的分工。后续从能力形态进入，结合已有计算器理解作者为什么偏向通用工具。

## 模型原生的主动工具发现：分两小段读

原文定位为同名小节（2026-09-16 核对），以下是助手按 Stage 3 范围给出的选择：

- 第一小段必读：标题下第一段、以“从被动选择到主动发现”开头的一段、以“工程上更常见的等价方案”开头的一段，共三个自然段，到图4-2之前停。理解为何初始查询无法预测所有工具需求，以及“模型表达能力缺口 → 系统匹配并加载定义 → 模型调用”的分工。MCP-Zero 的数字与产品名不背。
- 第二小段必读：图4-2及“层次化匹配与降级”一段，只抓先找服务器再找工具，以及找不到应明确反馈。嵌入索引、增量更新与阈值实现略过。
- 延后：“动态加载与 KV Cache”、图4-3/4-4和具体 API 字段；实验4-1的代码和运行不作为本阶段作业。小节末尾过渡段可略读，再进入 Skills。

对照已有代码：calculator-client.ts 的 client.listTools() 在 runAgent() 之前执行，程序取出 calculator 定义并构建注册表；这证明程序发现并接入了工具，不能记为模型运行中主动搜索工具。该实验使用 MockModel，未验证真实模型的搜索决策。

助手举例（未运行）：模型计算后需要保存说明，但当前可见工具没有保存能力，于是通过一个假设的工具搜索入口表达需求；系统检索已有工具目录并加载 create_draft 的定义；随后模型按 content 参数调用。查到定义不等于草稿已保存；没有匹配结果就反馈未找到，不能编造工具。
