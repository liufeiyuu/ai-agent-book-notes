## 第一轮：Coding Agent 怎样借助文件与工具完成修改

从章首导言开始，重点读“Coding 是 Agent 的基础能力”；“案例：从 Manus 到 OpenClaw——通用 Agent 的 Coding 内核”略读流程，重点取文件系统作用与末尾适用边界，到“Coding Agent 的整体流程”标题前停。此范围按一个完整问题组织，替代此前仅读导言三个自然段的机械切分；工具数量与具体产品断言不展开。

助手解释：文件系统保留材料、中间结果和代码，Agent 用工具读取和修改文件、运行代码、根据结果决定下一步。已有 calculator 是预先写好的能力；代码生成让系统遇到新需求时能够编写新的处理逻辑。后者仍需要可执行的环境和验证，不能只把生成的文字当成已经完成的能力。

作者在本章强调开放任务型通用 Agent 的 Coding 内核，这是有适用范围的架构观点。固定业务流程的 Agent 可以围绕既定领域工具组织；不把这一观点扩大为所有 Agent 都应随时生成并执行任意代码。带读时保留两条工程判断：能运行不等于满足需求；规则写成代码后仍可能写错或遗漏。

本例连接：计算器契约修复中，助手定位和读取实现、发现声明与校验不一致、修改校验、运行检查并根据反馈修正。这是已有证据；本次导读不重新运行，不记为学习者已完成 C 审查。
