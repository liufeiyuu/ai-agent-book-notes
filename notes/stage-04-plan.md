## A. 第 6 章：异步 Agent 与运行控制

先概览本章的两个维度：观察/动作的形式，以及交互的触发时机。语音、Computer Use 和机器人只用于认识不同交互场景，本单元实践集中在异步任务与运行控制。

**需要掌握：**

- 从一次调用中顺序等待工具，到后台任务与事件驱动的 Agent，运行方式增加了什么；仅使用 `async/await` 不能证明整个 Agent 可以响应外部事件。
- 启动长任务后如何立即取得任务 ID，任务尚未完成时怎样接收用户查询、补充要求或取消指令。
- 事件队列/分派器怎样处理用户输入与任务完成事件，怎样按任务 ID 关联结果，并在安全的处理位置更新轨迹、续接 Loop；接收输入不等于任意时刻并发修改模型消息。
- 一次工具调用的状态、一个 Agent Run 的状态和业务完成状态如何区分。
- `pending`、`running`、`waiting_approval`、`succeeded`、`failed`、`cancelled` 的含义与允许的转移。
- 权限与人工审批如何控制执行；批准的操作和参数需要怎样对应。
- 超时、重试、幂等分别解决什么问题；哪些失败适合重试，为什么需要上限。
- 取消怎样传递、为什么不等于撤销已有效果；恢复还需要保存哪些状态。Trace 记录不自动提供恢复能力。

### 核心实践：运行并理解 `async-agent`

阅读入口为[官方 `chapter6/async-agent`（实验 6-2）](https://github.com/bojieli/ai-agent-book/tree/main/chapter6/async-agent)。先看 README、事件/任务模型与调度入口，运行选定的离线最小路径；保留其与真实模型场景的区别。若采用 TypeScript 等价实现，记录为机制复现，不能记为已经运行了官方 Python 项目。

学习者亲自运行并追踪以下过程；可用受控任务与脚本化模型观察机制，不要求新增付费模型调用：

1. 启动一个尚未完成的任务，获得任务 ID 与运行状态。
2. 在它完成前发送查询或补充要求，确认输入能被接收；说明它被立即处理还是排队等待。
3. 任务完成后，按同一任务 ID 收到完成事件；结果与适用的用户更新进入下一轮处理，输出最终结果。
4. 改变一次取消或补充输入的时机，观察处理顺序、任务状态和最终结果的变化。

证据至少能串起“任务启动 → 中途用户事件 → 完成/取消 → 后续处理”，包含事件顺序、任务 ID、状态和结果回传。仅画状态图或给函数加 `async` 不算此项通过。离线验证证明运行机制；没有真实模型参与时，不声称验证了模型自主调度能力。

### 同一实验中的执行边界

复用[已有 Loop](../experiments/minimal-agent-ts/src/agent.ts)的轮数、超时和取消机制，以及[退款工作流](../experiments/refund-agent-real/src/workflow.ts)的阶段判断，先解释现有证据。

承接 Stage 3 的虚构草稿操作，用小型进程内演示观察以下边界：

| 场景 | 要观察的结果 |
| --- | --- |
| 尚未批准、批准、拒绝 | 未批准前不写入；批准来自测试驱动的用户输入，不能用模型自填字段代替；拒绝后没有草稿 |
| 相同操作重复提交 | 同一键、相同参数返回同一结果，只有一条记录；同一键配不同参数报告冲突 |
| 写入前取消 | 不再开始写入，运行记录为取消；另外解释写入后取消的局限 |
| 暂时失败与不可重试失败 | 确定性故障展示有界重试；非法参数和权限拒绝等先修正条件，不能盲目重试 |

学习者结合审批判断或重复提交判断中的一处修改讨论预期；助手实现并验证，学习者核对实际效果。案例共用一个小实验，不分别建设完整系统。

**完成证据：**异步任务完整事件记录、输入时机对照、状态图、边界结果和一次关键判断修改与学习者对其效果的解释（助手可代写）；能解释失败所在层次。数据库事务、并发竞争、Worker、崩溃恢复和跨进程幂等进入后端阶段；所选最小演示不记为这些能力已经实现。

## B. 第 7 章：评估与失败诊断

**需要掌握：**

- 将任务输入、初始状态、预期结果、过程约束与判定规则分开记录。
- 区分工具单元测试、Agent 任务评测和运行过程检查。
- 确定性检查、人工核对、LLM Judge 各适合判断什么；Judge 也需要标准与人工校准。
- 成功率、工具错误、步数、延迟、Token 和成本如何帮助定位问题；没有实际测量的数据记为未知。
- 样本如何覆盖正常、边界和失败，为什么少量案例通过不足以代表普遍可靠。

**最小实践：**将 Stage 3 已有的工具/Coding 检查与本单元 A 的正常、非法参数、拒绝、重复提交、取消和暂时失败案例整理成固定评测表。学习者讨论一条检查或一个已有检查遗漏的边界，由助手补代码并验证，不另建评测框架。

对照退款项目的[六个案例和验证器](../experiments/refund-agent-real/src/evaluation.ts)，选一个成功记录与一个失败记录，解释自动检查支持哪些结论、哪些仍需人工读证据。设计一条适合人工或 Judge 使用的简短评分标准，本单元不要求接入新的 Judge 模型。

**完成证据：**评测表、一次有原因的检查改动、一组成功/失败归因。复用真实 Trace，离线回放与新运行分别标记，不为收集指标而默认重跑全部付费接口。
