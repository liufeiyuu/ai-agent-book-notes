## B：Python 从零起步

按有编程经验的人学习新语言的方式推进，不重复从零讲编程概念。

| 学习块 | 必须会用 | 最小练习 |
| --- | --- | --- |
| 环境与模块 | 解释器、虚拟环境、包安装、模块导入、入口与配置 | 建立可运行项目，说清依赖装在哪、入口怎么执行 |
| 数据与函数 | 常用类型、列表/字典/集合、条件/循环、函数与参数 | 处理虚构工具记录，筛选失败并按工具汇总 |
| 类型与组织 | 类型标注、可选值、简单类或 dataclass、模块职责 | 表达输入和结果，区分类型提示与运行时校验 |
| 异常与资源 | 异常、清理、文件读写、JSON、日志和 traceback | 分别处理输入错误、格式错误、文件不存在 |
| 测试与调试 | pytest、断言、参数化、fixture、替换外部依赖 | 检查正常输入、非法输入与执行失败 |
| 异步入门 | async/await、协程/任务、等待与并发、超时和取消传播 | 用受控假工具观察一次成功和一次超时或取消 |

先将前五块汇成**一个本地 JSON 处理 CLI**：读取虚构数据 → 校验 → 按明确规则处理 → 输出结果与错误。学习者能查文档写出关键函数、改一条规则、运行测试并根据回溯定位问题，即可进入 C 的基础 API 学习。

异步入门接着把一个假工具换成异步执行，并在 C 接入模型与工具前完成。不要求先掌握并发框架或性能优化，也不以安装好 Python、读懂完整答案代表已经会写。

Pydantic 的请求模型与 FastAPI 一起学习。元类、复杂装饰器实现、解释器内部、多进程优化和完整生态留到需求出现时。历史 RAG 与记忆实验保留 TypeScript 成果，不要求重写一遍。

阅读入口：[Python 官方教程](https://docs.python.org/zh-cn/3/tutorial/)用于语言、模块、文件、异常和环境；[asyncio 文档](https://docs.python.org/zh-cn/3/library/asyncio.html)与[pytest 入门](https://docs.pytest.org/en/stable/getting-started.html)按练习问题查阅。

## C–F：围绕一条服务链路学习

目标链路：

```text
客户端提交任务
  → FastAPI 校验与身份范围检查
  → 创建 AgentRun
  → Agent Loop 调用模型和工具
  → 保存消息、事件和运行状态
  → 查询 / SSE 展示进度
  → 核对结果、失败或取消状态
```

### C. 先打通请求

学习 HTTP 请求/响应、状态码、REST、Pydantic 校验、依赖注入、配置与密钥、路由/业务/存储层边界。先用内存状态和受控模型验证，再接可用真实模型，不一开始迁移全部历史实验。

理解认证与授权的区别，以及请求身份如何可信取得。本地可用服务端绑定的虚构身份；客户端随意传入的用户 ID 不能直接当作已验证身份。

最小接口覆盖创建会话、提交任务和查询运行。学习者逐步写出 Python 简化 Loop 的核心，协议和工具脚手架可以辅助提供；能追踪输入到工具结果，定位参数错误与下游失败。TypeScript 实验用于行为对照。

### D. 再持久化事实

学习表、主外键、索引、基础 SQL、事务、SQLAlchemy 与 Alembic 的职责。建模 Session、Message、AgentRun、ToolCall、ToolResult 或对应事件，区分对话记录、运行状态和工具效果。

验证服务重启后历史仍可查询，并依据可信身份检查会话与运行的所有权，用户不能读到别人的记录。**历史可查询与任务可恢复分别验收**，恢复在 E 完成。

### E. 加入可靠的任务执行

把第四周的进程内边界放进真实服务：请求和后台任务的职责、状态持久化、超时、有界重试、退避、幂等、审批、取消、失败恢复。验证重复提交、部分失败、重启后的运行处理，以及过期或参数不匹配的批准。

学习 Redis 的缓存、TTL、短期状态和队列等适用场景，实际接入由服务需要决定；能说明与 PostgreSQL 的职责边界。用 Worker、数据库约束与操作幂等解决具体问题，不以安装了组件代表可靠性完成。

### F. 做成可使用、可诊断、可交付的服务

用 SSE 展示事件，前端提供运行状态、工具时间线、错误和取消/审批入口；认识前端断连与后台取消的区别。按运行 ID 关联日志和 Trace，记录实际可获得的步数、延迟、Token 与成本。

用 Docker/Compose、环境配置、迁移和健康检查组织启动；完成一次干净环境启动与失败排查，说明基本备份、发布和回滚办法。沿用前端能力做薄交互层，重点验证服务链路。

面向实际用户开放时接入最小认证，并验证对象授权和密钥隔离；不要求自行建设完整账号系统。

后端主教材：[FastAPI 官方教程](https://fastapi.tiangolo.com/tutorial/)。数据库、测试与部署资料在对应阶段开始时核对。

## G：项目与面试成果

- 根据兴趣、实际工作流和届时岗位需求选择主项目；旧草稿题目保留为候选。
- 先完成目标清楚、可使用的工作流，再补状态、权限、失败处理、观测、评测和部署。
- 从实际任务与失败补充评测；样本数量由覆盖需要决定，不凭数量认定质量足够。
- 保存架构、决策、失败改进、演示与运行说明，能解释哪些代码自己完成、助手怎样参与、证据支持什么结论。
- 多 Agent 与持续进化先补概念与取舍图：任务分工、上下文隔离、协调成本、产物更新和回归验证。项目确有收益时再实现，独立开项，不追加为第三周门槛。

模型训练、底层推理、复杂分布式系统、Kubernetes、大规模多 Agent、全套记忆治理继续按需深入。
