# 延后学习清单

这份清单用于贯彻“抓大放小”：当前阶段先搭建 Agent 工程的完整知识框架，不让非阻塞细节挤占核心学习时间。延后不等于放弃；当项目出现真实需求时，再带着问题深入。

## 分级规则

### P0：现在必须掌握

- 核心概念及其边界
- 组件职责和完整数据流
- 关键方案的适用场景与取舍
- 常见失败模式和诊断方法
- 最小可运行实现
- 能证明实现有效的评测证据

P0 的完成标准：能够用自己的话解释、闭卷画图、对具体场景做选择、实现最小版本，并通过 Trace 或测试验证。

### P1：项目需要时深入

- 参数调优和性能优化
- 框架或供应商的实现差异
- 生产级存储、缓存、并发和部署
- 更完整的安全、权限与治理机制
- 对核心结论有帮助但不阻塞当前理解的原理细节

### P2：有余力再研究

- 数学推导和模型内部细节
- 前沿论文与实验性架构
- 全量源码阅读
- 多模型、多 Provider、全参数组合复现
- 与当前项目没有直接关系的扩展能力

## 执行规则

1. 每个主题先明确 P0 问题，再开始阅读或实验。
2. 一个细节如果不影响主流程、方案选择或正确性判断，最多探索 10–15 分钟。
3. 超时仍未解决且不阻塞 P0 时，写入本清单并继续主线。
4. 每条延后项记录“为什么延后”和“何时重启”，避免只有一个模糊 TODO。
5. 项目遇到真实问题时，优先从 P1 清单中按需取回，不按章节顺序机械补课。
6. 各阶段先约定具体验收范围；记录学习者与助手各自完成的工作。已通过的核心验收不因新增选修练习而重置，助手实现不能记作学习者独立实现。
