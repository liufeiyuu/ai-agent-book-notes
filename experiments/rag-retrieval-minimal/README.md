# RAG 检索与重排序最小对照实验

## 实验目标

用一个确定性、离线的 TypeScript 实验理解三件事：

1. 稀疏检索与语义检索的盲区为什么互补；
2. `Recall@K`、MRR 和时效性检查分别回答什么问题；
3. 如何根据完整排名 Trace 区分召回、融合和重排序问题。

这个实验不调用模型、网络或外部 API。它的目标是学习检索管线和评测方法，不是比较真实 Embedding 模型。

## 实验前预测（原始回答）

### 1. 精确错误码

> A 和 C，因为稀疏检索可以根据关键词匹配到能够命中这个关键词的对应的文档片段，而混合检索加重排则是最完善的一种做法。它既融合了稀疏检索，又融合了稠密检索，同时还会对检索进行重排，所以它的效果最好的。

### 2. 语义改写

> 稀疏检索最容易失败，因为用户的这个问题比较抽象，很难以去准确地匹配到含有这个关键词的片段。

### 3. 新旧政策冲突

> 因为有可能在检索重排阶段，旧政策排在第一，新政策排在旧政策后面，还有可能在生成阶段，模型在分析的过程中出错了。

### 4. 综合预测

> C：混合检索 + 时效重排。

### 5. 结论边界

> 可以验证这三种策略的机制差异以及各自的优势，因为没有接入真实的模型，所以不能验证真实模型根据检索结果的生成能力。

补充限制：由于语义检索由人工概念标签代理，实验也不能证明真实稠密检索器或真实混合检索管线的效果。

## 控制变量

- 同一组六个文档；
- 同样的三个查询与正确文档标注；
- `Top-K = 2`；
- 相同的评测函数；
- 唯一主动改变的是检索策略。

## 三个测试场景

| 查询 | 主要考点 | 人为设置的干扰 |
| --- | --- | --- |
| `HTTP-403 怎么处理？` | 精确标识符 | 泛化的服务器错误文档 |
| `账号进不去了怎么办？` | 语义改写 | 字面命中“账号”的资料修改文档 |
| `现在退款期限是多少？` | 版本时效 | 2024 年 30 天旧政策与 2026 年 7 天现行政策 |

## 三种策略

1. `sparse`：可运行的 BM25 风格字面检索。
2. `semantic_proxy`：把人工概念标签转成 0/1 向量并计算余弦相似度；只代理机制，不是真实 Embedding。
3. `hybrid_rerank`：用 RRF 融合两路排名，再用精确标识符、语义相关性和版本状态重排。

## 运行

```bash
cd experiments/rag-retrieval-minimal
npm run demo
npm test
```

## 学习路线

不要通读整个文件，只按以下入口学习：

1. `buildCorpus`（第 75 行）与 `buildQueries`（第 128 行）：哪些文档是正确证据，哪些是干扰项。
2. `sparseScores`（第 182 行）与 `semanticProxyScores`（第 260 行）：两种召回信号分别看什么。
3. `hybridRerank`（第 334 行）：融合、精确字段保护和时效信号如何改变排名。
4. `evaluateRanking`（第 398 行）：`Recall@K`、MRR 和时效性为什么要分开检查。

## 指标

- `Recall@2`：本实验采用单一正确文档，因此表示正确文档是否进入前两名。
- MRR：第一条正确文档排名的倒数，再对三个查询求平均。
- `freshnessPassed`：现行政策是否排在已废止政策之前。
- `passesAllConditions`：三个查询的正确文档全部进入 Top-2，且现行政策排在旧政策之前。

## 实验结果

| 策略 | Recall@2 | MRR | 时效检查 | 全部通过 |
| --- | ---: | ---: | --- | --- |
| 稀疏检索 | 66.7% | 0.611 | 未通过 | 否 |
| 语义代理检索 | 66.7% | 0.556 | 未通过 | 否 |
| 混合检索与重排 | 100.0% | 1.000 | 通过 | 是 |

逐题结果：

- 精确标识符：稀疏检索把 `runbook-http-403` 排在第 1；语义代理将其排到第 6；混合策略恢复到第 1。
- 语义改写：稀疏检索将正确登录文档排到第 3，落在 Top-2 之外；语义代理和混合策略均排在第 1。
- 新旧政策：稀疏和语义代理都召回两版政策，但把 2024 年旧政策排在前面；混合策略用受相关性约束的时效信号把 2026 年政策排在第 1。

预测与当前合成实验结果一致。这里的“混合策略最好”只表示它在这三个特意构造的机制测试上同时通过，不代表实际系统可以直接采用相同权重。

## 一次有价值的失败

第一版实现把“当前有效”的正向权重加给了所有活跃文档，也把负向权重加给了旧政策。结果虽然 2026 年政策升到第 1，但四篇完全无关、只是状态为 `active` 的文档也全部超过了旧政策，旧政策掉到第 6。综合通过条件没有发现这个副作用，针对具体排名的第 5 个测试发现了它。

修正方法不是简单调大或调小权重，而是增加门控：只有候选与当前查询具有语义相关性时，才允许版本状态影响排序。修正后，新政策第 1、旧政策第 2，五个测试全部通过。

这次失败说明：

1. 时效性只能在相关候选之间比较，不能替代相关性；
2. “正确文档排第 1”仍不足以证明其余排序合理；
3. 聚合指标之外还需要针对已知风险设置局部断言。

## 实验限制

- 语义概念标签由人工提供，结果不能外推到真实 Embedding 模型；
- 文档和查询是为暴露互补失败模式而构造的合成数据；
- 重排序规则是确定性的工程规则，不是神经重排序模型；
- 没有生成器，因此不评价答案正确性、证据忠实度或引用质量；
- 单一正确文档使本实验中的 `Recall@2` 更接近 Hit@2，不覆盖多相关文档召回率。

## 学习者受控修改与结课

### 扩大 Top-K

仅将 `TOP_K` 从 2 改为 3，学习者观察到稀疏策略 Recall 从 66.7% 提高到 100%，但 MRR 和正确文档的位置不变。

解释：选取范围扩大了，评分与排序没有改善。登录文档的稀疏分数仍为 0，同分时按 ID 排到了第三；进入 Top-3 不证明检索器识别了查询语义。

### 关闭时效加权

恢复 `TOP_K = 2`，仅从最终求和中移除 `freshnessBoost`，保留其计算和 Trace 字段。学习者观察到 C 的退款查询中新旧政策交换位置，`recallAtK` 不变，`freshnessPassed` 从通过变为失败。

解释：在当前数据上，时效项改善的是版本排序，而非 Top-2 覆盖。只有对具体组件做消融，才能说明该组件的贡献；C 还包含标识符和语义奖励，全部收益不能归给 RRF。

### 恢复与验收

学习者恢复公式后确认五个测试全部通过，实验结束。2026-09-06 整理复盘时，源码已恢复而保存的 Trace 仍是消融结果，因此重新运行 `npm run demo`，编译通过并刷新基线：C 的 Recall@2 为 100%、MRR 为 1.000、时效检查通过。消融观察保留在本节，`latest-typescript.json` 用于当前基线。
