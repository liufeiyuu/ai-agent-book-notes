## 结构与数据流

1. `extractCandidate`：真实模型读取用户原话，提出 `{ value, evidence }` 候选。
2. `validateCandidate` / `applyCandidate`：程序检查字段、允许值及原文引用，再决定 ADD、UPDATE 或 NOOP。
3. `readMemory`：新进程按程序传入的用户标识和主题读取当前有效偏好。
4. `buildAnswerMessages`：将校验后的偏好转成表达风格要求，只加入当前问题，不带上次聊天。
5. 用户明确纠错后，更新同一用户、同一字段的当前记录，再由新进程读取验证。

| 文件 | 只需看的职责 |
| --- | --- |
| [src/memory.ts](./src/memory.ts) | 提取候选、构造新会话上下文；不负责写文件 |
| [src/store.ts](./src/store.ts) | 校验、按用户读取、保存和更新 |

`data/memory.json` 只保存当前偏好及来源、更新时间。旧值出现在历史 Trace 中，但不再作为当前事实注入。`runs/call-budget/1.json` 至 `9.json` 在发送请求前占用名额；失败尝试也计数，换用户或新进程不会重置。

## 环境与安全边界

- 复用 `minimal-agent-ts` 的 TypeScript、tsx 和模型适配器，无新增依赖。
- 配置只读复用现有本地配置加载器，当前使用 `deepseek/deepseek-v4-flash-0731`、非思考模式；不复制凭据或改配置。
- 真实 CLI 没有模拟开关，不使用正则或写死答案冒充模型提取。离线测试中的模型替身明确标注。
- `--user` 由本地教学程序指定，不是模型输出字段；这是用户隔离演示，不是生产认证。
- 只允许 `brief`、`detailed` 两个有效值。模型返回 `none` 则不写入；来源引文必须来自本次用户输入，但这个检查不能证明语义提取一定正确。
- `--topic other` 不注入代码讲解偏好。主题由教学命令显式提供，不宣称已实现自动相关性分类。
- 本地文件与 Trace 被 Git 忽略，只使用虚构数据；请求记录不含授权头，持久化和控制台输出会脱敏已配置密钥。
- 写入演示按顺序运行；没有实现生产级并发更新、事务、长期冲突治理或自动遗忘。

### 截断的诊断和已验证修正

失败响应实际消耗 900 个输出 Token，达到该请求的 `max_tokens: 900`，没有思考 Token。模型将“详细”展开为长篇 SDK 示例，因此不正常结束；这不是记忆未保存，也不是新会话未读取。部分文字虽已生成，但不能当作完整成功回答。

随后仅调整详细风格提示：约 250–350 个汉字、三个小段、最多 3 行 TypeScript 伪代码；保持模型、输出 Token 上限、记忆和提问不变。改进报错以展示实际 finish_reason，原始失败 Trace 保留。第 5 次实际使用 251 个输出 Token，`finish_reason=stop`，共有 441 个字符（其中 343 个汉字），不再展开完整 SDK 长代码。本次复验说明该样例修正后通过，不保证未来绝不截断；调用计数上限单独按用户授权调整为 9。

人工核对：回答确实比简短版展开，解释了模型发出调用请求、程序执行、结果返回模型的过程。它仍有“保证准确性”“避免模型直接操作系统的风险”等过于绝对的表述：工具结果也可能出错，外部执行不自动等于安全，仍需权限与参数校验。记忆使用通过不代表生成内容每一句都准确；本课不因此追加一轮接口调用或扩大为工具安全实验。
